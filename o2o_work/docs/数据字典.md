版本：2026-10-14。依据：本地输入、已执行profile.json/数据核验Notebook及项目大纲。数据页面：https://tianchi.aliyun.com/dataset/38115 。本次没有独立核实采集来源、样本代表性、再分发许可或完整字段说明。

|文件|粒度与角色|既有全量行数|

主键缺失；源行号是追溯定位字段，不证明业务事件唯一。保留完全重复记录，后续另做完全去重敏感性。线上原核验的重复数是64位行哈希筛查，不是业务重复证明。

## 原始字段

所有ID读为VARCHAR，避免浮点化、前导零损失和将ID作为可加总数值。字面量`null`及空值按缺失处理；原始层仍保留原始文本。日期原始格式YYYYMMDD，正式层转换DATE；无效非空日期单列异常，不静默丢弃。

|字段|类型化目标|含义与处理|
|---|---|---|
|User_id|VARCHAR|脱敏用户ID；独立用户须在对应群体内去重|
|Merchant_id|VARCHAR|脱敏商家ID；线上线下不可关联|
|Coupon_id|VARCHAR/NULL|券种ID，不是唯一领券实例ID；普通消费缺失|
|Discount_rate|VARCHAR/NULL|0.9为支付原价90%；100:10为满100减10；无券消费缺失|
|Distance|VARCHAR/NULL|仅线下。已核验编码0—10；未知保留独立类别，不能补0|
|Date_received|DATE/NULL|领券日；非领券事件缺失。领券群体需Coupon_id与该日同时有效|
|Date|DATE/NULL|消费日；线上点击/购买的事件日。未核销券Date缺失属于业务状态|
|Action|VARCHAR|仅线上；工作口径0=点击、1=购买、2=领券。该语义采用项目既定口径，未独立核实下载页面原始说明；新来源有冲突时复核|

Distance编码与精确公里/区间的映射尚未确认，特别是10的上界含义；本项目先保留编码，不猜测精确距离。Action=1存在Coupon_id与Date_received的记录，线上全部领券不能只筛Action=2。线上/线下用户ID既有重合267,448；商家和券ID既有交集为0。仅允许用户聚合后受控关联。

## 状态与派生字段（阶段1已实现）

|状态/字段|定义|
|---|---|
|普通无券消费|Coupon_id、Date_received缺失，Date有效；不进入领券核销分母|
|领券无消费日期|Coupon_id与Date_received有效，Date缺失；完整观察期内无已观察核销|
|15日内核销|有效领券且0≤消费日−领券日≤15，两端包含|
|超过15日消费|有效领券且lag_days>15；保留，不进入15日分子|
|异常|日期解析失败、消费早于领券、券与领券日不一致、未知Action、优惠格式异常等，阶段1定位|
|lag_days|真实DATE之间的自然日差；同日为0|
|receipt_month / receipt_weekday|按领券日期派生；星期口径统一ISO：周一1、周日7|
|coupon_type|直接折扣或满减；未知/异常单列|
|threshold / reduction|满减A:B的A和B；直接折扣缺失，不伪填金额|
|nominal_discount_fraction|直接折扣r为1-r，满减A:B为B/A；只描述名义优惠比例|
|mature15|领券日+15日≤指定观察截止日|
|source_file / source_row_number|源文件与从1开始的数据行号（不含表头）；技术定位，不是订单/券实例ID|

上述派生字段已在阶段1正式库data/o2o.duckdb中实现；阶段0数据库仍仅用于小样本环境验证。详细表结构见复现与交付说明.md及各次运行table_schemas.json。
